### Node Pools

Node pools are maps of objects representing each worker pool. Each pool supports the following fields:

| Name | Description | Type | Default | Notes |
| :--- | :--- | :--- | :--- | :--- |
| `count` | Number of nodes with dynamic IPs. | number | | Cannot be used with `ip_addresses`. |
| `ip_addresses` | List of static IPs for nodes. | list(string) | | Cannot be used with `count`. |
| `cpus` | Number of CPU cores per node. | number | | |
| `memory` | Memory in MB per node. | number | | |
| `os_disk` | Operating system disk size in GB. | number | | |
| `misc_disks` | Extra disk sizes in GB for `local-storage` class. | list(number) | `[]` | Only used when `local-storage` storage class is needed. See [REQUIREMENTS.md](REQUIREMENTS.md#storage). |
| `node_taints` | Taints applied to nodes in this pool. | list(string) | | |
| `node_labels` | Labels applied to nodes in this pool. | map(string) | | |

The `node_pool_defaults` variable sets defaults merged into each pool. The `node_pools` variable defines the actual pools.

> **Note:** Required pool names for SAS Viya: `control_plane`, `system`, `cas`. Additional pools (`compute`, `stateless`, `stateful`, `singlestore`) are optional but recommended.

#### Azure — node\_pools example

Azure pools use `machine_type` (VM SKU) and `data_disks` instead of `cpus`/`memory`/`misc_disks`.
See [`topologies/azure/sample-input-azure.tfvars`](../topologies/azure/sample-input-azure.tfvars) for the full example.

```hcl
node_pools = {
  control_plane = {
    count        = 3
    machine_type = "Standard_D4s_v5"
    os_disk      = 100
    data_disks   = []
    node_taints  = ["node-role.kubernetes.io/control-plane:NoSchedule"]
    node_labels  = {}
  }
  system = {
    count        = 1
    machine_type = "Standard_D8s_v5"
    os_disk      = 100
    data_disks   = []
    node_taints  = []
    node_labels  = { "kubernetes.azure.com/mode" = "system" }
  }
  cas = {
    count        = 3
    machine_type = "Standard_E16s_v5"
    os_disk      = 100
    data_disks   = [512, 512]   # mounted as local-storage disks
    node_taints  = ["workload.sas.com/class=cas:NoSchedule"]
    node_labels  = { "workload.sas.com/class" = "cas" }
  }
}
```

#### OpenStack — node\_pools example

OpenStack pools use `flavor` (Nova flavor name) to size nodes. `openstack_flavor_defaults` is the fallback when `flavor` is omitted.
See [`topologies/openstack/sample-input-openstack.tfvars`](../topologies/openstack/sample-input-openstack.tfvars) for the full example.

```hcl
openstack_flavor_defaults = "m1.large"   # fallback flavor for pools without 'flavor'

node_pools = {
  control_plane = {
    count       = 3
    flavor      = "m1.xlarge"
    os_disk     = 100
    misc_disks  = []
    node_taints = ["node-role.kubernetes.io/control-plane:NoSchedule"]
    node_labels = {}
  }
  system = {
    count       = 3
    flavor      = "m1.2xlarge"
    os_disk     = 100
    misc_disks  = []
    node_taints = []
    node_labels = { "workload.sas.com/class" = "system" }
  }
  cas = {
    count       = 3
    flavor      = "m1.4xlarge"
    os_disk     = 100
    misc_disks  = []   # add disk sizes here to enable local-storage class
    node_taints = ["workload.sas.com/class=cas:NoSchedule"]
    node_labels = { "workload.sas.com/class" = "cas" }
  }
}
```

#### vSphere — node\_pools example

vSphere pools use explicit `cpus`, `memory`, and `misc_disks`. Use `ip_addresses` for static IPs or `count` for dynamic DHCP.
See [`topologies/vsphere/sample-input-vsphere.tfvars`](../topologies/vsphere/sample-input-vsphere.tfvars) for the full example.

```hcl
node_pools = {
  control_plane = {
    count        = 3
    cpus         = 4
    memory       = 8192
    os_disk      = 100
    misc_disks   = []
    ip_addresses = ["192.168.1.10", "192.168.1.11", "192.168.1.12"]
    node_taints  = []
    node_labels  = {}
  }
  system = {
    count        = 1
    cpus         = 8
    memory       = 65536
    os_disk      = 100
    misc_disks   = []
    ip_addresses = ["192.168.1.20"]
    node_taints  = []
    node_labels  = { "kubernetes.azure.com/mode" = "system" }
  }
  cas = {
    count        = 3
    cpus         = 16
    memory       = 131072
    os_disk      = 350
    misc_disks   = [150, 150]   # two 150 GB disks → local-storage StorageClass
    ip_addresses = []
    node_taints  = ["workload.sas.com/class=cas:NoSchedule"]
    node_labels  = { "workload.sas.com/class" = "cas" }
  }
}
```

#### Bare Metal — node\_pools example

Bare metal pools reference pre-existing hosts by IP. There are no compute specs — the machines already exist.
See [`topologies/bare_metal/sample-input-bare-metal.tfvars`](../topologies/bare_metal/sample-input-bare-metal.tfvars) for the full example.

```hcl
node_pools = {
  control_plane = {
    ip_addresses = ["192.168.1.10", "192.168.1.11", "192.168.1.12"]
    node_taints  = []
    node_labels  = {}
  }
  system = {
    ip_addresses = ["192.168.1.20"]
    node_taints  = []
    node_labels  = { "kubernetes.azure.com/mode" = "system" }
  }
  cas = {
    ip_addresses = ["192.168.1.30", "192.168.1.31"]
    node_taints  = ["workload.sas.com/class=cas:NoSchedule"]
    node_labels  = { "workload.sas.com/class" = "cas" }
  }
  stateless = {
    ip_addresses = ["192.168.1.40", "192.168.1.41"]
    node_taints  = ["workload.sas.com/class=stateless:NoSchedule"]
    node_labels  = { "workload.sas.com/class" = "stateless" }
  }
}
```

### Labels and Taints

Add to `ansible-vars.yaml` to apply SAS Viya workload classes:

```yaml
node_labels:
  cas:
    - workload.sas.com/class=cas
  compute:
    - launcher.sas.com/prepullImage=sas-programming-environment
    - workload.sas.com/class=compute
  stateful:
    - workload.sas.com/class=stateful
  stateless:
    - workload.sas.com/class=stateless
  singlestore:
    - workload.sas.com/class=singlestore

    - kubernetes.azure.com/mode=system   # prevents SAS software from running on system nodes

node_taints:
  cas:
    - workload.sas.com/class=cas:NoSchedule
  compute:
    - workload.sas.com/class=compute:NoSchedule
  stateful:
    - workload.sas.com/class=stateful:NoSchedule
  stateless:
    - workload.sas.com/class=stateless:NoSchedule
  singlestore:
    - workload.sas.com/class=singlestore:NoSchedule
```

## Storage

An NFS server provides the `default` storage class (backed by NFS CSI Driver). A `local-storage` storage class is also configured when `misc_disks` are attached to worker nodes — used for applications requiring local (non-networked) storage such as CAS.

- See [REQUIREMENTS.md](REQUIREMENTS.md#storage) for storage hardware requirements.
- NFS server setup and the `local-storage` class are provisioned automatically when `create_nfs = true` (vSphere/OpenStack/Azure) or when the NFS server is listed in the inventory (bare metal).
